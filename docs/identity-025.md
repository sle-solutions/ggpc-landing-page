# Signup and private usage dashboard, 0.2.5 candidate

This source is private and not deployed. It consumes the identity API contract in the paired extension/API worktree. It does not register providers, create an administrator or activate analytics.

- `/signup?flow=<opaque>` reads safe metadata only after the server validates its named HttpOnly browser cookie. New users choose a configured Google or Discord provider. Existing password users have a separate sign-in form. Both submit the exact current terms, privacy and usage-consent versions and require policy acceptance; optional feature analytics is unchecked and independent.
- `/api/identity/[...path]` is a cookie-only, no-store, same-origin bridge to the fixed API. It refuses unsupported paths/methods, arbitrary target URLs, duplicate/unknown query keys, oversized bodies, unrelated cookies and unsafe upstream cookies/redirects. Beginning a browser flow on a website alias first redirects to the configured canonical host before creating its host-only cookie. It never forwards incoming Authorization or exposes a bearer handoff exchange.
- `/admin/usage` checks the server-held admin session before fetching reports. The public login shell contains no counts or report data. APIs deny unauthorized data access. Reporting shows real aggregate data only, UTC date/version filters, opted-in coverage, feature outcomes, daily activity, an ordered funnel, common paths, repeat-day groups, first-observed cohorts and bounded error/duration/result buckets. Empty and insufficient data remain empty.
- The root layout does not mount Vercel Analytics on `/signup`, `/admin` or identity API paths. Auth/admin response headers are no-store/no-referrer/noindex with a same-origin resource CSP and explicit trusted OAuth form destinations.
- API-only provider client secrets and the explicit ADMIN role are operator setup. No browser credential, JWT, provider token, account ID or raw usage event appears in a page model or aggregate response.

Local development uses the exact lock and pinned Node24.22.1. The API and website must explicitly share a local `IDENTITY_PUBLIC_ORIGIN`; `GGPC_IDENTITY_API_URL` can point to a loopback `/api/identity/` only outside production. Production defaults are the fixed GG PC website and Railway API. Do not weaken provider redirect, cookie or CSP protections to make a Preview login work.

Before activation: parent security review, actual provider setup and round trips, fresh production recovery before migration, coordinated API/site rollout, accepted policy and Store disclosures, required-signup gate tests and Store-delivered release verification. Root owns native browser checks. Public prices/quotes, Sheet operations, payments and member-code activation are outside this leaf.
